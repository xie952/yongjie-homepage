## 7. 禁区 / 铁律（摘要）

- **端口 5175**；npm 加 `--cache "./.npm-cache"`；禁杀全部 node  
- **一个元素一个 transform 源**（视差 / 视频 scale / 文字墨迹分属不同节点）  
- **视差 scroll 禁 setState**；视频禁再编码  
- **reduced-motion**：显 poster、动效直显，勿删对应 CSS

- **视频轨道**：`play()` 勿绑进文字时间轴 onComplete

- **磁性按钮**：只用 `MagneticButton`（渲染外更新，禁 useState 存位移）；只给 Hero 主按钮用，**严禁给 Dock 项再包一层**（Dock 自有 magnification）  
- **scrollRestoration**：每次 ST refresh 后需再 `lockScrollRestoration`  
- **Tab 样式**：按钮必须有 `tab-btn` + `is-active`（曾因删 class 导致切换器变纯文字）  
- **历史段位纹章**：只在 RankBadge 内用 `contain`，禁止 cover 裁切

- **内层皮肤子卡片框**（`.hero-card .skin-item` / `.weapon-card .skin-item`）读**主题色**（`var(--hero-theme-rgb, var(--rarity-rgb, 212,175,55))`，静止 0.5 / hover 0.95 / 光晕同色）；变量链自带 `--rarity-rgb` 回退，所以**没有主题色变量的卡行为与改动前一致**。英雄卡那份另叠 0.14 主题底色，武器卡不叠（武器皮肤行原本就是透明底）

### 8.5 ⚠️ 环境坑：`npm run build` 不会清空 `dist/`（本次实测，非项目配置问题）

**现象**：`dist/assets` 里堆着历次构建的旧 bundle（本次清理前有 4 个孤儿文件，最早来自上一次会话），
`vite build` 每次只写新文件、不删旧文件。

**实测取证**（三步，可复现）：

1. 往 `dist/` 放探针文件 `__probe_stale__.txt` → `npm run build` 之后**它仍在**；
2. 直接验证 Node 能力：`fs.writeFileSync` 正常，但
   `fs.rmSync(p, { recursive: true, force: true })` **既不抛错、也不删除**（文件仍在）；
3. 同一台机用 PowerShell `Remove-Item` **可以正常删除**。

**结论**：Vite 的 `emptyOutDir`（内部即 `readdirSync` + `rmSync`）在**当前受限运行环境**下被静默无效化。
不是项目配置问题 —— `vite.config.js` 没有关它，Vite 也没打印
`outDir is not inside project root` 警告。在沙箱外的普通终端里构建，`dist` 会被正常清空。

> **补充修正（2026-09-30，见 §24.3）**：上面第 2 步的「**既不抛错、也不删除**」只在**经 Vite 调用**时成立。
> 直接调用 `fs.rmSync` 实测会**抛错**：`Error: EPERM, Permission denied: \\?\D:\DSH\...\dist`
> （`code: 'EPERM'` / `syscall: 'rm'`）。也就是说删除动作本身是被**拒绝**的（EPERM），
> 是 **Vite 自己把异常吞掉**了，才表现为"静默无效化"。
> 结论（受限环境下 `dist/` 删不掉）不变，但排障时别照"不抛错"去判断 —— 自己写清理逻辑必须 try/catch + 回读验证。

**每次构建后的建议动作**（本次已手动执行一次，清理后 `dist/assets` 只剩当前产物）：

```powershell
Remove-Item -Recurse -Force dist
npm run build
```

> 保留旧产物的副作用：`serve-main.mjs` 没有发送 `Cache-Control`，若浏览器缓存了旧 `index.html`，
> 页面会继续加载旧 bundle，让人误以为「改的东西没生效」。所以每次构建后请**强刷** 5175。

**该待办已于 2026-09-24 完成（见 §13）**（⚠️ 服务器代码改动需**重启 5175 才生效**）：给 `serve-main.mjs` 补缓存头 —— `.html` 发 `no-cache`、
带 hash 的 `assets/` 发长缓存。这能一次性消掉上面那个"缓存旧 bundle"的坑。

### 13.3 核心改动

**A. 缓存策略（`serve-main.mjs`）**

改前：所有响应都**不带 `Cache-Control`** → 浏览器走「启发式缓存」，可能长期留着旧 `index.html`，
而它引用的 `assets/index-<旧 hash>.js` 早被新构建顶掉 → 页面加载的还是旧 bundle，观感就是「改的东西没生效」（§8.5 记录过）。

改后按「文件名是否带内容 hash」分档（只看请求路径，不引入构建清单文件）：

| 请求 | Cache-Control | 理由 |
| --- | --- | --- |
| `/`、`/index.html` 等 `.html` | `no-cache` | 入口每次都回服务器核对，永不滞留旧版 |
| `/assets/*`（Vite 产物带内容 hash） | `public, max-age=31536000, immutable` | 内容变 → 文件名必变，可放心长缓存 |
| 其余（图片 / 字体 / 视频） | `public, max-age=3600` | 同名替换时最多一小时后自动更新 |
| 404 | `no-store` | 旧产物下线后不被缓存挡住 |

同一份文件里顺带两处收口（同类问题，一并处理）：

- **文本类型补 `;charset=utf-8`**（HTML/JS/CSS/JSON/TXT），扩展名统一 `toLowerCase()` 后再查表 ——
  站内素材是**大写 `.PNG`**（`guqhan.PNG` / `tongling.PNG` …），改前查不到映射，被当 `application/octet-stream` 发出去（**已实测复现**，见 13.5）。
- **路径越界收口**：改前 `join(ROOT, url)` 直接拼接，`/../serve-main.mjs` 之类能读到 `dist` 之外；
  现在先解码 → 由 `join` 规范化 → 校验「必须仍在 `dist` 内」，越界一律 404。

**B. 页脚日期口径（`ContactSection.jsx`）**

现象（可复现）：`tianxuan.lastUpdated = "2026-09-14"`，页脚却显示 **2026-09-13** —— 整体少一天。

根因：`new Date('2026-09-14T00:00:00')` 是**本地零点**，而 `toISOString()` 会折算成 **UTC**；
东八区下就是 `2026-09-13T16:00Z`，再 `slice(0,10)` 自然拿到前一天。

修法：不再经过 UTC，直接用本地年月日拼串（新增 `formatLocalDate()`），与 `daysSince()` 的本地零点口径对齐。

同时修掉**同源的第二个偏差**：`daysSince()` 原先用 `new Date()`（带时分秒）当「今天」，
于是**同一个页面上午访问显示「10 天前」、下午就变「11 天前」** —— 现在「今天」也取本地零点。

### 14.2 ① 卡片动效：根因是选择器失效，不是「没做」

**根因（代码级确证）**：`choreo.js` 用 `statGrid.children` 过滤 `.stat-card` 收集卡片；
MagicBento 接入（§11/§12）后网格的直接子元素变成 `.magic-bento-card`，`.stat-card` 被包在里面 →
`statCards = []` → 天选/征神两段的数据卡入场整段空转；而 `takeOver()` 已摘掉这两块的 `data-reveal*`，
两边都不管 → 静默零动画。

**实测对照**：`#tianxuan .stat-grid > .stat-card` = **0 个**（嵌套 14 个）；`#wujian .stat-grid--5` 未接 MagicBento，
直接子元素就是 `.stat-card` → 5 张卡照常有入场动画（同一份代码、同一个选择器，接入与否结果相反）。

**改法**：新增模块级判定 `isStatCell()`（`.stat-card` 或 `.magic-bento-card` 都算一张卡），天选与征神共用；
同时把「逐卡 `delay: i*0.07`」换成单次 `stagger: 0.06`（tween 数下降），并给每张卡补第二层
「指标名 → 数值」错峰。末卡延迟封顶 0.42s，避免 14 张卡把后面的「常用英雄/武器」编排推后近 1 秒。

### 14.3 ② 版块反差：令牌梯度太窄（不是没分层）

**根因**：`--bg #0b0a09` / `--bg-2 #100f0d` / `--panel #161412` 三级亮度差极小（相对亮度 0.0031 / 0.0048 / 0.0071），
且版块只用二分交替（`.mode-section:nth-of-type(even){background:var(--bg-2)}`）→ 卡片对版块底只有 1.04–1.14:1，
肉眼几乎同色（整屏像素亮度实测：Hero 53.3，其余 5 段只有 17.6–24.0）。

**改法**：
- 新增 4 档明度令牌 `--tone-0…--tone-3`，按段分配（Hero 最深 → 档案 t1 → 天选 t2 → 征神 t1 → 无间 t3 → 收尾 t2）；
  版块底色渐变改读 `--sec-bg`（未 assign 的段回退 `--bg`，行为与改前一致）。
- 新增卡面令牌 `--panel-sec`（默认回退 `var(--panel)`，**版块外的卡片外观完全不变**），
  版块内覆盖为 `--card-surface`（现值 `#3e3932`，2026-09-25 二调，见 §14.10）；`.stat-card` / `.hero-card` / `.weapon-card` / `.build-card` /
  `.zs-progress-card` / `.treasure-item` 六处卡面改读它。渐变第二档用 `color-mix()` 从同色派生，**不新增硬编码色值**。
- 卡面被抬亮后，卡内次要文字同步提亮：`--muted` 只在卡片容器内改写为 `--muted-card`（实测标签对比度 5.08:1，维持 AA）。

**调参入口**：想整体加减卡面亮度只改 `--card-surface` 一个值；想换档次只改 `--tone-*`。

### 14.4 ③ 滚动驱动：新增版块级 scrub 层（segments.js）

**实测背景**：改前全站 31 个 ScrollTrigger 里只有 1 个是 scrub（顶部 2px 进度条）；
用「下行扫一遍 + 上行再扫一遍（once 入场已消费）+ 静止对照」三种相位分离后，
`#profile` 及以下 4 段在**上行相位的变化元素数 = 0** → 滚动过程本身不产生任何画面变化。

**改法**：新增 `src/lib/segments.js` —— 每段一个 `scrub: 0.6` 的 ScrollTrigger（`start:'top bottom'` → `end:'bottom top'`），

1. `.seg-aura`（JS 注入的氛围层，每段一枚，按段着色 `--seg-tint`）：`y 44→0`、`opacity .42→1`；
2. `.mode-head` / `.closing-head`：`±13px` 微视差。

**铁律遵守**：只写 transform/opacity；触发元素是版块本身（非 sticky）；`.mode-head` 自身不被 choreo/fx 写 transform；
在统一启动序列第 ④ 步（定位完成、入场系统创建）内调用；reduced-motion 直接跳过（不注入氛围层、不建 ST）。

### 20.1 先更正一条：手机端导航「偏右」是测量假象

上一轮是用 browser skill 的设备模拟测的，报出「左边留白 61px、右边不足 4px，右边缘越界 6px」。本轮改用独立 CDP 探针复测，确认**那是模拟层自己的假象**：

| 证据 | 读数 |
| --- | --- |

## 21. 「常用英雄 & 武器」轮播：点卡切换（2026-09-27）

### 21.1 落地语义：走一格，不是跳到该卡

点左侧可见卡 → 上一张居中；点右侧可见卡 → 下一张居中；居中卡不响应；隐藏卡不响应。

**注意这与改动前的行为不同**：旧代码是 `onCardClick(i) { if (i !== active) setActive(i) }` —— 点哪张就跳到哪张。本轮按需求改为「向该侧走一格」，已实测确认（见 21.4 倒数第二行：点 |d|=2 的远处可见卡，01 → 07 而不是 06）。

### 21.2 改动清单

| 文件 | 改动 |
| --- | --- |
| `LoadoutCarousel.jsx` | 新增 `TAP_MOVE = 8` / `TAP_TIME = 350`；新增 `tapRef`（按下点 `{x, y, t, idx}`）；`onPointerDown` 记录按下点与命中的卡序号；`onPointerUp` 改为「拖拽优先、否则判点击」；新增 `tapCard()`；**删除旧的 `onCardClick` 与 `<article onClick>`** —— 点卡判定不再走 click 事件 |
| `LoadoutCarousel.jsx` | 修掉自测中暴露的一个 bug：`dragRef` 原先只存 `x`，于是 `dy = e.clientY - undefined = NaN`、`Math.hypot(dx, dy)` 为 NaN、`NaN < 8` 恒 false → 点击完全不生效。现改为同时存 `y` |
| `LoadoutCarousel.css` | `.lo-card` 的 `cursor` 由 `pointer` 改为 `default`（居中卡不可点）；新增 `.lo-card:not(.is-active) { cursor: pointer }` |

### 21.3 三个关键实现决定

1. **判定放在 pointerdown/pointerup，不用 onClick。** click 表达不了「按住时长」；且指针越过 6px 会 `setPointerCapture` 到舞台，click 的 target 被重定向到舞台，基于 click 的判定会被静默吞掉（原型期踩过，代码注释里原本就记着）。
2. **方向在 pointerup 时现算，且用函数式 `setActive`。** 按下到抬起之间轮播可能已经动过一格，不能在 pointerdown 时算死；函数式更新还保证连点每次都以最新 active 为准，CSS transition 被最后一次目标覆盖 → 天然「不排队、以最后一次为准」。
3. **`onPointerUp` 里必须先 `classList.remove('is-dragging')` 再改 active。** 因为 `.lo-stage.is-dragging .lo-card { transition: none }` —— 顺序反了，点卡切换会变成瞬移，与箭头切换的 620ms 过渡对不上。

「上浮」仍用独立属性 `translate`（内联 `transform` 归 JS 管），本轮未动。

### 23.1 落地方式：一层底色 + 一个新模块

滚到哪个板块，整页底色就在 700ms 内平滑换成该板块的主题色。实现只有三处：

### 23.3 实测踩到的两个坑（都不是猜的，是量出来的）

1. **`IntersectionObserver` 的选项名是 `threshold`，不是 `thresholds`。** 写成 `thresholds` 会被当未知键**静默忽略**，阈值退化成默认的 `[0]` —— 只在「相交 ↔ 不相交」翻转时回调。而 `#profile` 在初始状态 `isIntersecting` 就已经是 `true`（ratio 为 0 也算相交），滚进去时状态不变 → **回调永不触发**，覆盖比例永远停在初始值，表现为「档案区死活不换色」。隔离实验对比：错键名滚动后仍是 1 次回调、ratio 卡在 0.000；正确键名是 2 次回调、ratio 0.688。
2. **防抖必须带尾沿补偿。** 第一版是「窗口内直接丢弃」，结果快速滚动（如 0 → 5600 连跳）时最后一次切换被丢掉，**底色永久停在上一段的颜色上**。改成尾沿触发（窗口结束时再判一次）后，5/5 快速跳转全部落在正确板块。

### 25.2 缺陷 A：交界「死区」——底色误回退 Hero 档，且不继续滚动就永不纠正

复现（`repro-4949.mjs`，真实滚轮 6/6/8 格，两次运行一致）：

```
停在 y=4949   inline --section-bg = ""（已被 removeProperty 抹掉）
              body background-color = rgb(11,10,9) = #0b0a09（Hero 档）
同一时刻的真实几何   zhengshen r=0.48   wujian r=0.52
              ← 按规则 wujian ≥ 0.5 应胜出 → 期望 #201c18
静止等待 2s / 5s    颜色一直不变（不是"过渡没播完"，是判定结果就是错的）
```

**根因**：`evaluate()` 直接吃上一次 IO 回调写进 `ratio` 的**缓存比例**。IO 只在**跨过阈值**时才回调，
缓存最多滞后一个阈值步长（`0.02 × 板块高度` ≈ 28px ≈ 视口高度的 3.5%）。板块交界处两段的旧比例
**可能同时略低于 50%** ⇒ `pick()` 返回 `null` ⇒ `apply(null)` ⇒ 回退 Hero 墨色；
而静止不动时不再有回调，**这个错误结果不会被重算**。

**修法**（1 行）：`evaluate()` 判定前先同步 `measure()` 一次实时几何；IO 回调不再自己算比例，
只当"该重新判定了"的信号。这样"是否有板块过半"永远按**当下真实几何**判定。

### 25.3 缺陷 B：sticky Hero 与 `#profile` 的重叠窗口整段不判定

`sweep.mjs` 在 4 个交界处 ±300px 每 60px 扫 50 点，扫出 **5 个错点**：y=870/930/990/1050/1110 —— 
实际停在 Hero 档，而规则要求 `#121110`（该区间 Hero 与 `#profile` 的覆盖比**同时为 1.0**，
按代码里"平局取文档靠后"的取舍，应当是压在 Hero 上面的 `#profile` 胜出）。

**根因**：这是 `IntersectionObserver` 的**固有盲区** —— 板块一旦占满视口，`intersectionRatio` 就恒定不动了
（Hero 恒为 1.0；`#profile` 一旦铺满视口下沿就恒为 `810/1178 = 0.6876`）。
于是 y≈810~1178 这**整段约 370px 的滚动区间内不会有任何 IO 回调**，判定一直停在进入该段之前的档位。
缺陷 A 的"实时重量"修法**救不了它**：没有回调进来，`evaluate()` 根本不会被调用。

**修法**（+8 行）：补一个 **rAF 节流的被动 `scroll` 监听**做兜底触发。
它只读几何、只写一个自定义属性：不 `preventDefault`、不碰 Lenis、不注册任何会拦截滚动的行为，
因此不会与入场动画 / 数字滚动 / hover 抢滚动（文件头原来那句"不注册滚动监听"已同步改成
"一个 rAF 节流的被动滚动触发"）。

## 29. 收尾页大标题「偏移」根因与修复（2026-10-02）

- A1 首次 mousemove：先把 `gsap.set(spotlight, { left: e.clientX, top: e.clientY })` 落到光标，再走 opacity 淡入 → 消除「从文档底部 7307.95px 飞入」；
- A2 跟随：`gsap.to(..., duration: 0.1)` → 改用 `gsap.quickTo(spotlight, 'left'/'top', d, 'power3.out')`（单例补间、不叠加）。换算依据：偏移 ≈ 速度 × d → 3106px/s 时 `d=0.1` 是 92px、`d=0.05` ≈ 46px、**直接 `gsap.set`（d=0）= 0px**。
- 建议 **A1 + 直接 set**（工单验收要求「偏移归零」）；若要保留一点拖尾手感，则 A1 + `d=0.05`。影响 3 个板块，均属纯改善。

**B. 入场卡顿（二选一，或 B1 之后视情况叠加 B2）**
- **B1 关掉 stat 网格的入场模糊**（推荐，视觉代价最小）：给 `revealCardGroup` 的 legacy 分支增加「每组可选模糊」的读取（`group.dataset.revealBlur`，缺省 = 现状 → 对未标记的组零波及），并在三个 stat-grid 上写 `data-reveal-blur="0"`。
  - 实测依据：`filter:none !important` → max 175.8 → **97.0ms**、`>100ms` 帧 **3 → 0**。
  - 代价：卡片不再从模糊中显形（仍有 40px 位移 + 0.96 缩放 + 淡入）。
- **B2 把计数挪到入场之后**：`StatCard.jsx:21,35` 的 `countDelay` 由卡片入场时长推导（`|dist|×0.12 + 0.9s` ≈ 0.9–1.68s）。
  - 实测依据：`noCount` → max **66.6ms**、`>100ms` 帧 **0**。
  - 代价：数字先停在 0 约 0.9–1.7s（与 `StatCard.jsx:17-18` 注释的初衷一致，但整体节奏变长）。
- 反面清单（实测无效，不要走）：单纯给计数降频（25Hz/卡仍 200ms）、加 `will-change`、去掉位移/淡入。
